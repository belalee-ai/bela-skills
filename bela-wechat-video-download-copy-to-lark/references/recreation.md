# 用户选择复刻后的需求与制作入口

## 先询问，再形成具体需求

归档完成后主动问“是否需要复刻这条视频？”。只有用户选择需要，才进入新视频制作。不要因为技能支持复刻就提前生成、使用账号额度或改动已归档原视频。

可以分成“用我的素材复刻”“制作新的 AI 素材”“暂不复刻”三种选择；如果用户说需要但没有确定方式，先把可行方式及需要的输入说清楚。用户已有的决定继续沿用，不重复提问。

## 复刻必须参考的官方资料

- [Hypit 官方网站](https://hypit.ai/)：查看当前产品说明、制作方式、服务与交付能力。
- [Hypit 官方 GitHub](https://github.com/hypit-ai/hypit)：查看 README、安装/更新说明、最新发布、技能和示例。

这里的产品是 **Hypit**。这两个地址是制作工具的官方资料，不等于当前被拆解视频的作者工程仓库。用户说的“Happy”不要扩展成另一个产品，也不要声称这个仓库包含该博主视频的源文件。

开始复刻时实际打开这两个官方来源，并按具体问题阅读当前文档、相关 release notes 与已安装最新 hypit skill。不要仅凭保存的链接声称已经查阅最新资料。上游不可访问或关键版本/能力不能核实时停止，说明需要恢复访问/依赖或补充依据；不能凭旧描述承诺新的能力。

## 详细需求清单

将本次分析中的具体事件变成问题，不能只问泛泛的“什么风格”。对已知项给出建议默认值，请用户确认或改动；只收集缺失信息。

| 需要明确 | 应向用户提出的具体要求 |
| --- | --- |
| 复刻目标 | 是保留原片结构做新主题、保留口播只换包装，还是尽量贴近原片效果？发布平台、受众、想促成的行动是什么？ |
| 文案与事实 | 新视频完整文案或要表达的要点；产品/名称/数字的准确写法；必须保留与不能改动的内容；最终行动引导。 |
| 人物和声音 | 使用用户自己的口播/配音素材，还是生成新的出镜角色/旁白？是否需要保留原声？不要默认复制参考博主的脸和声音。 |
| 输入素材 | 需要的视频、音频、图片、Logo、品牌字体/色值及真实产品界面；说明清晰度、横竖屏、时长、是否可裁切和哪些素材必须出现。缺文件时说明所需附件，不在仅支持文本的问答工具中要求上传。 |
| 保留与改变 | 列出本次拆解里最关键的 3–5 个机制和时间点，让用户选择保留/改造，例如同屏对比、数字强化、关键词入场、卡片展开、镜头移动；同时明确不需要的效果。 |
| 画面规格 | 比例、分辨率、帧率、目标时长、字幕语言、是否需要封面。可建议沿用源片规格，但不要把时间码机械复制到不同语速的新文案。 |
| 声音处理 | 旁白语气、语速、音乐方向、音效密度、原声保留方式。声音来源和服务选择明确后才执行。 |
| 交付形式 | MP4 是否足够，是否还需可编辑工程/素材包；明确实际工具支持的工程格式。未验证导出/导入链路前不能承诺剪映草稿。复刻产物单独放新制作目录，不破坏原归档目录的三文件结构。 |
| 服务和预算 | 使用哪些已经安装且就绪的服务、哪个计费账号、预算上限、覆盖哪些识别/生成/渲染。无预算授权不提交付费请求；新增依赖仍必须安装后通过门禁。 |
| 验收与进度 | 先确认脚本与代表段落，再检查成片；用户最在意的人物表现、内容准确性、效果或可编辑性；期望完成时间及需要的修改轮次。 |

可把低风险规格作为明确建议，避免让用户逐项从零设计；关键人物、内容事实、付费与工程格式不靠猜测。多项文字问题可合并成一张待补充表；有意义的创作选择可分轮提问。

## 进入制作的条件

1. 写 `BRIEF.md`：用户目标、已知事实、素材、规格、授权范围和预算；写 `TREATMENT.md`：结合具体参考机制提出的新片方案。
2. 检查新增生产依赖，逐个核实将用到的 skill 最新版本，有新版按精确范围自动升级并重读；缺 skill/CLI/模型或服务未就绪时停止，让用户安装/准备后复检，不静默改后端。
3. 按最新 Hypit 的相关制作参考准备脚本、语义时序、素材请求和组件。将新片事件绑定到新文案/动作，参考片时间码只作证据。
4. 代表段落和成片必须按真实输出检查；能听辨则检查声音，不能验证必需能力时停止补齐。交付新视频时说明实际交付物、工程可编辑范围和限制。
