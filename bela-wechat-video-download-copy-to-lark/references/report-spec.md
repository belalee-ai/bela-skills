# 拆解报告要求

报告是目录中唯一的结论文档，使用在线 docx；口播稿是另一份只记录原话的 `.md` 文件（见文末「口播稿」）。它必须在不阅读聊天记录时仍能理解，且能回到原视频核查。

建议保留这些内容，按视频长短合并或调整篇幅：

1. **素材信息**：博主（注明确认来源）、原始标题、来源分享链接、已上传原视频链接、时长/画幅/分辨率/帧率、分析日期。说明下载的是已发布成片，保留原字节，不等于相机素材或工程。
2. **核心结论**：视频承诺什么、面向谁、如何说服/叙事、最值得借鉴的关系；受众定位若是推断就明说。不要套用上一个视频的“自动化/可编辑”结论。
3. **时间轴**：时间、口播/动作、画面/字幕/图形的出现变化、对观众的作用。标明近似秒数或逐帧精度，保持源媒体时钟一致。对所有主要段落覆盖至结尾。
4. **证据图**：选择能证明结论的带时间码网格，例如开场、关键变化、兑现、结尾。图为原视频提取，图下词语来源与校对程度明确；Markdown 图片用已验证的 `@./` 本地引用语法。
5. **视觉与节奏系统**：主讲画面、插图/实录/示意界面、普通字幕、重点字、卡片、转场、层级、配色；说明何时出现、持续、退出以及跟随哪个语义。重复系统不必逐次重复解释，但例外和变化要定位。
6. **声音**：只写真实听辨或可核查的发现。ASR 文字和画面波形不足以评价 BGM、音效、响度或声音表演。无法听辨则准确标注；必需能力缺失不能继续交付。
7. **复用建议**：将有效机制转成适用于新素材的结构或制作要求，解释适用条件。若写 Agent 提示词，明确“本次分析归纳的示例”，不得冒称作者原版模板或网站原文。
8. **证据边界和方法**：区分成片观察、作者陈述、分析判断；记录 Hypit/所选识别方式、抽帧策略、校对范围和未验证工程/性能。未知制作工具、真实耗时和传播指标保持未知。

报告里不放整份逐字稿，需要引用时选支持论点的短片段；完整原话放口播稿。原始 ASR JSON/SRT、词级对齐、完整网格留在本地工作目录，不作为额外云端子文件。不要为了凑齐模板而编造声音结论或动作细节。

创建报告后必须回读全文而非只看创建回执：标题、时间轴、图片数量、最后章节与末段都应存在。飞书正文图片应为已上传的图片 token，而不是本地路径字串。

## 口播稿

文件名取 `archive_names.py` 输出的 `transcript_filename`，作为原生 `.md` 上传到同一目录。它是“这条视频说了什么”的可直接复用文本，不写分析。

1. **头部**：博主（及确认来源）、标题、分享链接、时长、识别方式（如 Whisper small 本地识别）、校对方式和日期。
2. **正文**：按语义段落分组（如开场、第一步…结尾），每段一个 `[mm:ss–mm:ss]` 时间码，后接校对后的原话。时间以 ASR 为准，保持源媒体时钟。
3. **校对**：以烧录字幕为准逐段修正 ASR 的同音错字、品牌和专名，直接写进正文，不另记改动。字幕没覆盖到的词，只有同屏文字、作品描述或上下文能给出明确依据时才改，并在正文该处标 `〔存疑〕`；没有依据就保留 ASR 原文并标 `〔存疑〕`。不要润色、补句或改写成书面语，口头禅和重复按字幕保留。
4. **无口播段**：只有画面或音乐的区间标为 `[mm:ss–mm:ss] （无口播：<画面简述>）`，不能当作静音推断。
5. **画面文字**：只在补足原话语义时附注关键屏幕文字，用 `> 画面文字：` 标出，和口播区分开。
6. **结尾**：**不保留校对记录**（ASR → 字幕的改动表不写进口播稿，原始 ASR 留在本地工作目录即可）。只写一节「待人工校对」，逐条列出正文里标了 `〔存疑〕` 的地方：时间码、识别原文、现在采用的写法和依据，供使用者需要时对照原视频人工确认；没有存疑处就写“无”。最后一句说明“自动识别＋字幕校对，未逐字人工听写”。
