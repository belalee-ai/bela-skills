# 贝拉视频号下载、拆解与飞书归档

输入一条或多条 `https://weixin.qq.com/sph/...` 链接，完成下载、拆解和归档。使用者已配置本流程后，只发链接即可启动，无需每条重复询问保存位置、命名或普通上传许可。当次明确说只下载、只查看或不上传时，以其范围为准。

## 默认位置和三文件结构

默认目标：**“贝拉自媒体秘密基地”知识库中唯一名为“视频拆解”的节点**。它可能位于“视频号”等父节点内，不能只查根目录。可配置其他知识库、完整节点路径或 Wiki URL；当次精确指定优先。不存在或同名歧义时停止询问，不能创建另一个默认知识库、上传云盘根目录或套用别人的历史链接。

```text
贝拉自媒体秘密基地
└── … / 视频拆解
    └── {MMDD}-{博主名称}｜{视频标题}
        ├── 【视频】{博主名称}_{视频标题}.mp4
        ├── 【口播稿】{博主名称}｜{视频标题去掉末尾。}.md   [原生 .md 文件，带时间码的校对口播稿]
        └── 【视频拆解】{博主名称}｜{视频标题}      [在线 docx，含证据图]
```

命名规则（全部由 `archive_names.py` 生成，不手拼）：

- 目录：以**归档当天日期 `MMDD-`** 开头，月、日都补零（如 `1031-`、`0902-`）。
- 目录下三项不加日期，统一用类型标签开头：`【视频】`、`【口播稿】`、`【视频拆解】`。
- 视频文件名的博主和标题之间用 `_`；口播稿和拆解文档用 `｜`。标题保留完整原文（含句末标点），只有口播稿文件名去掉标题末尾的「。」；拆解文档不再加“——视频拆解”后缀。

每条视频独立目录，**恰好三个直属文件**。图片嵌入拆解文档；封面、原始 ASR JSON/SRT、网格和拆解的本地 Markdown 不作为第四个云端文件。口播稿规则见 [报告要求](references/report-spec.md#口播稿)。Wiki 目录用 docx 节点承载，不能传不存在的 folder 类型。原视频指下载的已发布成片，不是相机素材或剪辑工程；保留文件字节，不转码覆盖。

## 0. 严格门禁：未通过不能开工

先读 [配置与版本检查](references/setup-and-updates.md)，运行 `scripts/check_dependencies.py`，再完成依赖技能的联网版本检查、所选服务和账号就绪检查。**任何环节卡住就停止后续流程，保留已有结果，准确报告阻塞。**

必需技能：`wechat-video-downloader`、`hypit`、`lark-shared`、`lark-wiki`、`lark-drive`、`lark-doc`。必需运行环境和 CLI：Python 3、requests、Node.js、npm/npx、技能管理 CLI、Hypit、FFmpeg、FFprobe、lark-cli，加上所选转录模式的 CLI、模型或服务。`lark-markdown` 不属于本流程依赖。

- **缺失、不可执行或不兼容：** 列出缺什么、用途和安装方法，明确请用户安装/修复。等待安装完成并重新通过整个门禁，才能继续。不得自动安装缺失项，不得先做后补，不用其他工具、浏览器、账户或仅看字幕的简化方案绕过依赖。
- **已安装的依赖技能过期：** 每次使用前从其原安装源检查最新版；只自动升级本流程所需的技能，重新读取新版 SKILL.md 并复检。此授权不包含自动安装缺失项、升级全部无关技能、升级 CLI 或下载模型。
- **最新状态不能核实或升级失败：** 停止。文件存在、CLI 版本号、缓存和 lock 记录都不能单独证明技能最新。具体版本核验与精确升级方法见参考。
- **账号/权限/余额/配额/目标/模型失败：** 准确分类，保留原始错误并给出修复要求。不能把它们误报成“重装即可”，不能静默换后端、切 bot 或扩大权限。
- 付费识别或生成前必须已有明确的计费账号、范围和预算；配置了凭据不等于新增费用授权。

执行中发现新依赖也返回门禁。用户修复后重新检查并从清单中的未完成步骤续跑；不得重复下载、收费或创建云端内容来掩盖失败。

## 1. 配置和目标解析

配置优先级：当次明确指令 > 用户指定配置 > 技能旁 `config.local.json` > `config.example.json`。模板字段为准；本地配置只保存非秘密路径和偏好，API key/token 留在环境或官方凭据存储。分发包排除本地配置。

按 [飞书参考](references/lark-archive.md) 全程 `--as user` 解析目标。完整路径逐层精确匹配；只有叶子名时完整遍历指定空间；分页以 `has_more` 结束。唯一命中才继续，保存本次运行的 ID/URL 到 `work/receipt.json`，不写入可分发技能。

## 2. 解析和保存原视频

读取已通过版本检查的 `wechat-video-downloader` 及核心流程，调用其真实接口/脚本。解析成功后立即下载临时直链；解析成功不等于文件已保存。下载/元数据 API 报错时按原始错误停止，不能转其他抓取路径绕行。

工作文件放当前任务 `work/<来源标识>/source/`，交付文件放 `outputs/`。FFprobe 确认流与时长，检查非空、可解码，记录大小和 SHA256。不得转码覆盖源文件，不在分享包中记录 key 或临时签名直链。

作者、标题以可信作品元数据为准。接口 title 若塞了整段描述，取首个非空标题行，完整描述另存。

接口没有返回博主名称时（红狐当前响应只有 title/desc/cover/videoUrl/resources，通常拿不到作者），**视频已下载成功后**用 Claude in Chrome（使用者自己的 Chrome）打开同一条分享链接，读取视频画面**左下角的博主名称**：

1. 新建标签页打开分享链接，等待页面加载；优先用页面文本/可访问性树读取左下角作者名，读不到再截图放大左下角核对。
2. 只取页面明确显示的视频号名称原文，不从人脸、水印、口播或描述推测；页面要求登录、扫码、验证或显示“仅在微信打开”时，不代为登录或绕过。
3. 读到后记录 `author_source: chrome_page` 到任务清单，关闭本次打开的标签页。
4. Chrome 未连接、页面打不开或左下角没有名称时，停止并只向用户询问缺失名称。

这一步只用于补作者名，不替代下载：下载/元数据 API 报错时仍按原始错误停止，不能改用浏览器抓取视频。不要用“未知博主”或编造标题冒充满足命名。

调用 `scripts/archive_names.py --url <分享链接> --author <博主> --title <标题>` 生成名称；日期前缀默认取本机当天，需要别的日期时加 `--date MMDD`。脚本仅处理文件名非法字符、长度及稳定后缀，保留完整元数据。将来源、名字、哈希、阶段状态记录到任务清单。

## 3. Hypit 拆解

读取最新 `hypit` 技能、reference-video 参考及本技能 [分析参考](references/hypit-analysis.md)。固定配置中的转录模式：默认 `whisper-local`，使用依赖检查自动解析出的 Whisper 命令和已下载模型文件路径（配置里不写死机器路径）；只有用户明确配置才用 `hypit-transcribe`。失败不能切换模式，也不能自动下载模型。

使用 Hypit 从开头到结尾检查带词语的时间网格，对密集变化与关键转折加密抽帧。按实际时长适配，不只看封面或几张代表帧就宣称完成。保留原 ASR，核对名字、品牌和烧录字幕；自动识别不是已验证原话。

保留 `ANALYSIS.md`、`TIMELINE.md`、转录和证据。按 [报告要求](references/report-spec.md) 生成独立可读的 Markdown：整体结论、时间轴、视觉系统、论证/故事、可复用方法、证据与限制，嵌入少量支持结论的 Hypit 时间网格。同时按其中「口播稿」一节生成 `transcript_filename` 对应的口播稿：以 ASR 时间为骨架，用烧录字幕逐段校对并直接改进正文；不保留校对记录，结尾只列「待人工校对」的存疑处，供需要时人工确认。

区分直接观察、作者声称和分析判断。没有工程就不保证剪映兼容性；没数据就不称高完播/爆款。没有真实听辨能力时不声称听过音乐/音效；允许该范围时写明限制，若完整声音分析必需就停止补齐能力。不得把依赖故障包装成“限制”继续归档。

## 4. 创建、上传和回读

先查目标下同名目录及任务清单。已完成且来源一致则返回现有链接；中断任务复用已验证 token，只补缺项。不同来源同名或无法核实来源时询问，不覆盖或盲目重复创建。

按飞书参考创建目录、上传原 MP4、创建带图片的拆解 docx、上传口播稿 .md；每步成功立即记录返回 ID/URL。结果未知先查服务端，不盲目重试写入。成功信封为 `ok: true`，不是顶层 `code: 0`。失败即停止并说明哪些已完成。

回读文档，检查标题、时间轴、预期图片数、末节末段；列全目录直属子项，核对**视频 file＋拆解 docx＋口播稿 .md file，共三项**。不自动删除其他资料，不改共享权限或发送消息。所有最终链接来自本次账户返回的 origin 和 token。

## 5. 完成后询问复刻

先给目录、原视频、拆解文档、口播稿链接与必要限制，随后必须问：**“是否需要复刻这条视频？”** 可提供“用我的素材复刻／制作新的 AI 素材／暂不复刻”。如果用户已经明确需要复刻，则不重复问。

用户选择复刻后，读 [复刻需求及官方资料](references/recreation.md)，根据本次视频具体拆解提出详细要求，收集素材和决定，写成 BRIEF/TREATMENT。重新检查新增依赖与技能最新版本，明确费用、交付格式和验收后再制作。不得把下载/拆解授权视为自动生成视频的授权。
