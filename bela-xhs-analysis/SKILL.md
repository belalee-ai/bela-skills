# 小红书竞品分析

## 目标

把真实小红书内容转成可验证的内容判断，而不是只复述标题、点赞数或生成通用模板。

用于账号任务时，先读取用户提供的项目简报和内容方向。

项目入口、用户本次意图和真实抓取结果优先于旧报告和 Skill 内示例。

## 入口判断

识别链接：

- `/user/profile/`：博主主页分析；
- `/explore/`、`/discovery/item/`：单篇笔记；
- `xhslink.com`：先解析短链，再判断类型；
- 多条链接：默认做逐篇提取和横向比较。

结合用户措辞直接判断：

- “分析这篇、给逐字稿、拆内容”：单篇模式；
- “分析博主、研究竞品、看这个账号”：博主模式；
- “比较这几条”：多篇模式。

只有用户只发链接、且不同模式会显著改变工作量时，才问一个关键问题。

## 获取真实内容

按当前可用性选择最短路径：

1. 先检查 `agent-reach doctor --json`；小红书后端可用时优先使用 OpenCLI 获取页面、笔记和评论数据。
2. 需要复用登录态、执行页面脚本或读取 `window.__INITIAL_STATE__` 时，使用 `bb-browser`。
3. 普通打开、截图、DOM 查看和交互验证可使用 `agent-browser`。
4. 上述路径不可用，或用户不愿复用浏览器登录态时，再使用本 Skill 的 Python 抓取脚本。

不再使用旧 `web-access`、Claude in Chrome 专有调用链或不存在的工具名。

浏览器和脚本的具体提取方式按需读取：

- `references/js-extraction-templates.md`
- `references/cookie-setup-guide.md`
- `references/media-extraction.md`

## Python 降级路径

脚本入口：`scripts/xhs_scraper.py`。

```bash
# 主页
python3 scripts/xhs_scraper.py "<profile_url>"

# 单篇
python3 scripts/xhs_scraper.py "<note_url>" --note

# JSON
python3 scripts/xhs_scraper.py "<url>" --json
```

Cookie 只能保存于被 `.gitignore` 排除的本地 `.env`，不得在对话、日志或报告中回显。用户未配置 Cookie 时先使用可行的无 Cookie 或浏览器方案，不默认要求用户提供敏感信息。

连续异常、403 或空数据时停止重复请求，保留已取得内容并明确缺失字段。

## 证据状态

分析前先区分已经取得的内容：

- 标题、正文、作者、发布时间；
- 图片和 OCR；
- 视频和口播转写；
- 互动数据；
- 评论原文；
- 博主主页和历史笔记。

没有取得正文、视频或评论时，不得写成“完整拆解”。需要时先输出一行：

```text
证据状态：已取得……；缺失……；以下结论适用到……
```

所有数据保留来源 URL 和抓取时间。评论归类必须能回指原文，不得虚构用户需求。

## 单篇模式

默认输出：

1. 笔记概况和证据状态；
2. 完整正文、OCR 或口播原文；
3. 标题、开头、主体、结尾和画面结构；
4. 可核验的评论需求；
5. 可以学什么、不能照搬什么；
6. 转成用户自己内容时需要补的真实素材。

用户只要逐字稿时，先交付逐字稿和转写准确性说明，不强制扩成完整竞品报告。

## 多篇模式

默认输出：

1. 核心数据和证据完整度对比；
2. 跨笔记共同结构；
3. 表现差异及可能原因，明确哪些是推断；
4. 评论需求共性；
5. 3-5 个基于证据的选题启发。

## 博主模式

默认分析：

- 定位、受众和内容形式；
- 近期选题结构和高表现样本；
- 标题、封面、开头、话术和画面证据；
- 收藏型内容、评论需求和未满足问题；
- 用户与竞品的差异空间；
- 少量有优先级的选题建议。

没有粉丝、收藏、评论或完整历史数据时，省略对应定量结论，不用估算冒充事实。

## 本地竞品库

只有用户明确要求“入库、建档、更新竞品库、以后持续追踪”，或当前项目任务本身就是维护既有竞品库时，才调用 `scripts/library/`。

端到端入口：

```bash
python3 -m scripts.library.orchestrator --url "<小红书链接>" --industry "<行业>"
```

执行前读取：

- `references/competitor-library-flow.md`
- `references/user-config-guide.md`
- `references/meta-json-schema.md`

不要因为用户只说“分析一下”就擅自建立长期档案。已有档案时优先增量更新；覆盖、归档和保存个人画像前遵循当前授权边界。

## 媒体提取

需要逐字稿或图文全文时，读取 `references/media-extraction.md`。OCR 和转写原文必须保留，摘要放在原文之后并标明是整理结果。

依赖缺失时说明缺失项和降级结果，不把“脚本存在”说成“转写已经完成”。

## 输出边界

- 不直接搬运竞品文案、画面和结论作为用户原创；
- 不编造页面数据、评论、发布时间和用户画像；
- 不自动生成完整口播、封面和发布包，除非用户明确继续；
- 不把小红书正文当作视频口播原文；
- 不把文件落盘、脚本成功或日志成功当成抓取完成；
- 不在报告中泄露 Cookie、私人路径、账号信息和未公开资料。

## 验收

- 链接和内容真实可回读；
- 证据状态与缺失字段清楚；
- 推断和事实分开；
- 输出与用户选择的单篇、多篇或博主模式一致；
- 生成文件时给出真实路径并回读关键内容；
- 运行脚本改动后执行 `scripts/run_regression.sh`。
