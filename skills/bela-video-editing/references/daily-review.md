# 每日使用复盘与精简

本文件供现有“剪辑 Skill 每日复盘”自动化及明确的使用复盘请求读取，不是另一套剪辑流程。新片仍走[唯一入口](../SKILL.md)，制作标准按命中的平台专项；这里仅定义何时复盘、优先修什么、怎样避免规则膨胀。

## 1. 有实际使用才复盘

- 每天北京时间 23:00 检查。以 Asia/Shanghai 自然日归组；从自动化上次成功截止点接续到本次触发，首次接管保留原有未覆盖窗口。当天 23:00 后的工作在下轮接续，不遗漏；失败窗口不推进成功截止点。
- 先看相关本人剪辑聊天及实际执行证据：用户的剪辑请求/纠正、Skill 调用或该工作流的实质制作、当前工程可读状态、对应素材/审片记录。标题、文件 mtime、素材存在和助手自述只作定位，不能单独证明使用或通过验收。
- 手动维护 Skill、自动化自身读取 Skill、单纯聊选题不当作新增剪辑使用。先筛相关聊天，再有界翻页到检查窗口；只有摘要或部分消息时标证据范围，不能把没找到说成确定没用。
- 没有实际使用且无未处理积压时，不改 Skill、不制造日报；无新问题、结果无变化且无需行动时保持安静。保留简短截止点、已处理根因和待验收项在自动化自身记录，同一天重复触发只处理增量。

## 2. 检查覆盖，按影响选最多五项

先查下面所有适用类别，再挑最值得处理的最多 5 个独立根因；不足 5 个不凑数。一个根因造成多次返工合并为一项，不用 5 个小问题挤掉一个大问题。

| 检查类 | 需要找到的真实证据 |
|---|---|
| 开工与素材准备 | 口播/工具/素材分工/进度条四项是否早已明确；真实缺口是否先说明，助手能做的是否自行完成 |
| 头像、脸部、抠图 | 椭圆/头顶/肩颈、遮挡、嘴型源时钟、透明边缘、卡顿和前后显隐；抽帧与连续检查分开 |
| 录屏与 B-roll | 口播对象/动作是否对应、完整窗口/行/操作链、手机尺寸、相邻及前后素材重复、有效变化 |
| 口播与逻辑 | 吞字、重说、犹豫/长等、自然呼吸、句间节奏、音画同步；钩子和最强亮点是否及时出现、先后逻辑是否易懂 |
| 花字、字幕、动效、转场 | 文字/字形与语义、单行皮肤、可读性、入场/落稳/退场、承接对象与重复机制，是否有不必要小字/硬闪 |
| 音效与混音 | 打字/点击/翻页/冲击是否贴实际动作，攻击点、清脆度、手机可听性、口播遮盖、多层衰减；是否真实试听 |
| 进度条与时间线 | 是否主动判断加不加、选择是否落实，章节/词级/全片进度语义是否真实；删句后各层及内部时钟、末尾是否同步 |
| 制作过程与 Skill 本身 | 工具/素材/模型阻塞、失败重试、可用本地替代、用户重复纠正、无效/重复/冲突条款、验证是否虚报 |

排序：P0 优先处理信息/语音受损、证据错配、漏画面、错时钟与明确遮挡；P1 处理影响理解、观看节奏和反复返工的开工缺项、选镜、钩子、声音问题；P2 纯装饰或影响很小的差异默认略过。相同错误被反复指出、跨片复发、影响时间长、修复可验证的优先；无证据的主观猜测不排成确定故障。

区分用户**新需求/探索偏好**与助手**没落实已知要求/已修后复发**。对话长不自动说明 Skill 失败；已明确的要求仍需用户重复提醒、同一问题多轮才处理、没有验收就称完成，才是需要修执行门的证据。

## 3. 解决问题与保留用户控制

- 有充分证据的 Skill 缺漏/冲突、重复路由和失效执行门直接修；沿用 skill-creator 的备份、差异回读和相关验证。不为“每天进化”每天加新条款。
- 对本周期仍在制作、用户已授权编辑的工程，可直接修复**边界明确、可回退、不改已确认内容**的问题，例如误留的旧叠层、错误显隐、与现行口播不符的源时钟/字幕/音效位置；先读最新工程和用户手调，留下可恢复状态，按该工具契约验证。没有可恢复状态或有并发修改时先保留现状并报告具体修法，不覆盖新改动。
- 吞字/气口等问题要有原声与实际回听，不能只看字幕自动重剪。钩子/亮点前置先给可复查的源句和重排方案；当前未锁定且已有重排授权时可做可回退草稿并验证，已确认结构、原声内容或范围会改变时列入需要用户选择的建议。已发布/已锁定的视频只提建议。
- 缺素材优先检查现有原件和可用本地制作路线；确需用户补录时给具体内容与用途。工具/音频/连续画面不可访问时保留证据缺口，不假称已解决。模型无法实际观察/听音不因计划存在而变成已验收。
- 每次问题闭环是 `证据/时间点 → 影响与根因 → 当前规则是否已有 → 修复或建议 → 实际验证/剩余缺口`。完成的修复不再当未解决问题重复列出，下一次检查是否复发。

## 4. 精简与交付

- 先检索命中条款：已有规则没执行，就补触发点、决策或验收，不复制近义禁令。优先替换/合并旧条款，入口保持短，细节只在一个平台专项维护；检查对应路由能否到达。
- 只有能改变下一次决定的可复用方法才进 Skill；单片秒点、坐标、音效曲目/dB、工具报错和执行记录留在本片/自动化记录。不要从一次审美取舍改全局皮肤或跨平台默认。
- 修复后回读文件/工程，核对相关引用与格式，用失败情形和正常情形检查是否误伤。格式校验、抽帧、连续播放、实际回听、最终文件和发布状态分别报告，不互相代替。
- 有实质结果时简报：覆盖了哪些当天实际使用；按优先级列最多 5 项 `问题/影响 → 已修内容或下一步 → 验证/待确认`；附必要产物。另用一句说明本次合并/替代了什么，或为什么无需改规则。不发长审计流水账，不列低影响事项凑数。
- 自动化不得新增付费、安装、登录或权限，不删除/移动原素材，不擅自整片导出/发布、不向其他聊天或外部服务发送消息；不改全局 AGENTS、Codex 记忆、无关 Skill 或其他作者项目。用户后来明确授权的动作以当次授权为准。
