# Little Move 小红书多轮返工复盘

日期：2026-11-04。来源：本次对话中 Lidali 对多轮剪辑的直接反馈，以及对话里已读回的工程参数/画面。此文件保存案例和规则检查依据，不作为下一条视频的默认预设。

本次授权只维护 Skill；没有重新剪辑、导出或验收这条视频。过去的参数写入、合成抽帧和短音频文件不证明已实际听过、所有帧流畅或已发布。尤其不能把没有听觉输入能力时的波形/峰值检查写成“听感已通过”。

## 问题到规则的对应

| 可观察问题 | 失效原因/应检查的根因 | 规则改动与下次触发 | 通过证据 |
|---|---|---|---|
| 竖版头像顶头、脸/肩颈被切、椭圆有尖角 | 把素材框或圆角当实际人像轮廓，只验正面静帧 | 精修 §1；第一次用头像先找极端动作，保持人物比例和光滑椭圆，给头顶留白 | 合成中正脸、最高/最低头位与手势连续播放；嘴型同源 |
| 横录屏缩得太小，放大后又丢结构/漏半行字 | 安全区被当成整张窗口的内缩框，盲目 cover 或局部取景 | 精修 §2；先定整体/操作/局部任务，保持比例用足宽度，查整个运动区间 | 手机尺寸下整行可读，输入—反馈关系存在，滚动落稳不留半行 |
| 让录屏完整后，却保留几十秒等待 | 混淆内容链完整与时间原样保留 | 精修 §2；保留开始与完整结果，中间等待按状态边界压缩 | 连续播放可复述真实操作，回复/结果未截断，不伪装实际耗时 |
| 乱码/花字素材不知道在解释什么，闪现和转场生硬 | 按效果名称挑图，没有口播任务和承接对象；同一动作反复填空 | 精修 §2、§4；先对应口播的对象/动作，再锁完成态与转场 | 去掉声音仍能辨认对象，接点无错位/闪底，重点落稳可读 |
| N 遍抠图不干净、卡顿、前后起止不一致 | 前景/底片源帧不一致、内部延迟与外部时窗不同；也可能有蒙版/透明素材解码负担 | 精修 §3；按实际源映射生成局部前景，同时检查蒙版边缘和性能，不只挪时间线块 | 眨眼、嘴和手连贯；文字可见期间每帧都有正确前景，退出不残留 |
| 去停顿后仍卡住，另一处却吞字 | 没把低能量尾音、呼吸与无信息空等分开；仅依 ASR/波形或短淡化验收 | 小红书 §0 精修顺序；先源句恢复，再调空白与呼吸；查相邻句节奏 | 实际回听完整前后句及整段，字词完整且没有不必要的空等/黏连 |
| 打字声几轮提高后仍偏小，音色闷且不贴动作 | 通用“压在人声下”取代了可听性判断；没有听源声音、攻击点和手机输出，也未验证语义配声 | 精修 §5；真实输入对应敲键，按正常手机音量比较开/关和候选，查重复衰减 | 实际听得到输入反馈，停打即停，清脆短尾且口播字词清楚；写入增益只证明配置 |
| 用户加素材/删句后后半段错位，结尾双头像 | 主口播、字幕、B-roll、头像内部源时钟和音效有的前移、有的没移 | 小红书 §5、精修 §7；回读用户最新手调，按当前源映射逐层重对齐 | 检查删点前后和后半段语义节点，结尾人声与各层结束范围一致 |
| 缺外部/付费工具就停在解释或转交用户 | 把供应商功能与制作任务混为一谈，没有最小本地验证 | 精修 §6、调用地图；在授权与工具契约内试原生/代码/局部辅助路线 | 有可检查的局部结果并接回原母版；仍缺能力时明确具体缺口而不虚报 |

## 静态场景推演

以下检验规则能否给出具体决策，不是已经在新视频上实测通过。

| 输入情形 | 按现行规则应发生的行为 |
|---|---|
| “横向录屏不要那么小，铺满一点” | 等比使用宽度、保留结构；先减外围空白/次要层，不能裁成竖屏 cover |
| “这段 AI 回复播放完整，但别让我等 30 秒” | 保完整回复和结果，中间等待压缩；不截半句，不原样留 30 秒 |
| “椭圆上面尖、没头顶空白” | 重看高低头极端帧，修实际椭圆和取景；不能改成正圆或拉伸脸 |
| “身后字还在，透明人像结束了” | 查共同可见时窗与内部延迟，并重算底片源帧；不能只延长最后一帧 |
| “去掉嗯和停顿” | 分清语义/呼吸/空等，保完整讲法；不全词表删、不让必要尾音淡没 |
| “打字声再大 50%” | 先读当前值，对指定音效线性乘 1.5（约 +3.52 dB），再做可听性检查；不动口播 |
| 只是正常的硬切真人口播，没有 UI 操作 | 可以不加装饰转场和音效；不强制调用精修全部工具或付费生成 |
| 缺听音能力但工程已写入音效 | 技术排查并交付同母版短试听，清楚标听感未验收；不能称已听清 |
| 外部生成器不可用，但本地代码/蒙版可用 | 先验证最难短段并接回；不能因插件缺失把常规制作丢给用户，也不绕过权限拒绝 |
