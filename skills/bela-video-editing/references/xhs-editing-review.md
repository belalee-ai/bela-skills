# 小红书分支：粗剪、制作与对抗检查

适用于 Lidali 本人小红书的真人口播、真实录屏和成果演示。**新片先读[小红书现行样式卡](xhs-style-card.md)**：人像形式、底图、导航、花字场景、B-roll 素材顺序、音效色板和样片要求都在那里，本文件不重复。选材方法视频号也可以复用，视觉规范各自独立。画幅、每 3–5 秒有效变化、剪口回听和整条复核见[共用剪辑规则](editing-rules.md)；字幕皮肤见[小红书字幕](xhs-subtitles.md)。单片事件和参数留在案例复盘，不作跨片默认。

网络新闻视频、人像陪伴或配乐起势问题，同时读[新闻解释专项](news-explainer-review.md)的对应小节；那里的案例原本按视频号制作，它的绿底字幕、固定双行标题和视频号速度不迁到小红书。教程仍按实际操作和结果组织，不因热点案例要求全程 B-roll。

头像、完整录屏、身后花字/抠图、闪现转场与音效的实际制作，按[小红书动效与声音精修](xhs-motion-audio.md)读取命中节；不是只在用户指出问题后才读。该专项包含源时钟、椭圆蒙版、完整窗口、等待压缩、音效可听性与本地替代路线。

## 0. 真人口播粗剪

当次明确要求和用户后续手调优先。

- **速度：有效口播 `1.1×`**（小红书唯一定义处）。已有变速先核对源片和工程，不再乘一次。
- **画面**：按[共用画幅](editing-rules.md#账号与画幅)。人像形式按[样式卡](xhs-style-card.md#1-开剪前要问清的两件事)由视频类型决定；裁切保留完整脸部、嘴部和必要动作，不拉伸源片。
- **开头**：第一秒用原素材里最相关的冲突、反差、痛点、结论或金句，前三秒建立观看理由；无关的动态片段不优先于清楚的观看承诺。保留的“Hello，这里是李贝拉Bela”用本人原声紧跟钩子，在前几秒出现；不从寒暄开场，不合成素材里没有的口播，ASR 把名字认错时以原声为准。
- **清理**：删重说、忘词间隙、失败的半句话、重复啰嗦、无效闲聊和铺垫；长气口压缩，短的自然气口保留，不吞字。先按下方精修顺序拆开呼吸与空等，再取切点；只保字不清空等、或为清空等切断字词，都不通过。「嗯、啊、然后、就是、其实」只在纯犹豫或重复垫话时删，承担顺序、因果、判断、转折或个人语气时保留。
- **筛选与逻辑**：优先留核心干货、真实观点、抓人的原话、真实评价、适用条件和可执行建议；没有新增信息的泛泛夸赞、重复强调和铺垫可以在授权范围内删。先抛痛点或结论，再讲原因、给方法；已经顺畅的讲解不为套顺序打断。重排时注意代词有所指、逻辑连贯，不拼出没说过的观点。个人身份句和收尾按当前明确要求处理，一次重剪不变成永久删除规则。
- **时长**：没有默认秒数。用户没给目标时长时，开剪前问一句要剪到多少秒；按最终 1.1× 时间线计。优先删重复和铺垫，不为凑时长加内容，不靠继续加速、截字尾或删必要观点达标，也不宣称时长能保证完播率。
- **范围与声音**：粗剪只做裁切、排序、气口和必要的音频切口，不加复杂特效。口播为主；有 BGM 时不盖人声，粗剪不主动新增音乐。单段过长按完整语义选切点，不机械跳切。
- **重复诊断**：用户说某秒重复时，听这个剪口前后完整一句，区分真实重说、字头泄漏/尾音截断、爆破音和正常停顿。ASR 会漏重说，两份转写的边界差异也会造成假重复；只删字幕或叠淡化不算修好声音。喷麦、底噪、音量、口误分开处理（见[共用混音通则](editing-rules.md#配乐音效与混音通则)）。
- **后续包装**：从锁定的口播继续铺字幕、真实网页和贴片，所有时序按当前速度重算。人像大小和显隐按当次简报和视频类型，一次的选择不覆盖其他片子的构图。

### 气口与吞字的精修顺序

1. **先听原句和现有剪口。** 以完整意群为单位，区分字头/尾音、连读、真实吸气、句间停顿与犹豫空等；波形、VAD、ASR 帮助定位，不把低能量直接当静音。本条明确给了停顿阈值，就记入简报，在当前成片速度下逐段扫描整条口播并复扫修改后的版本，连片头、片尾一并核对。未指定时检查约一秒的无信息空等、句中卡住和短垫词，按实际回听判断气口。阈值用于找候选，切点保留完整字音和必要呼吸。
2. **先保完整讲法，再压空白。** 选择最顺的一次表达；取点先给两侧留源把手，听清尾音和下一字起音后向内微调。呼吸与空等连在一起时可保留自然呼吸、压缩前后多余空白，不用“保呼吸”留下整段长等候，不把一句的字头当上一段的尾巴删掉。
3. **两种相反失败都要查。** 单句逐段听没有断字，还要连续听相邻几句：是否有“说半句就停一下”、吸气被放大、句句黏连、突然抢拍、删掉转折或重说残音。宁可保留短而必要的气口，不靠提高全片速度掩盖卡顿。
4. **吞字先回源恢复。** 从原始录音恢复被截断的完整字词及尾音，再重设切口；不要用淡入淡出、配乐、B-roll 或合成声音盖住缺字。淡化按接缝需要设置，短字的起音不能被淡入压没。
5. **修完再验收。** 回听前后至少各一句并连续听整段；批量清理后整条听一次，覆盖开头、所有修改的接缝和结尾。不能实际听音时先做源映射与保护柄修复、生成可定位的短试听并注明未完成听感验收；不能只凭字幕顺或波形正常声称“无吞字、气口自然”。

## 1. 从观看任务倒推剪辑

| 第一性问题 | 剪辑决定 | 能观察到的通过条件 |
|---|---|---|
| 观众看完要理解什么、能做什么？ | 一条观看承诺串起成果、输入、修改与结果 | 零背景观众能复述“给了什么参考、说了什么要求、哪里变了” |
| 这句话需要什么证据？ | 给参考时展示输入，提修改时展示真实请求，讲效果时播放结果 | 口播指向的对象和变化在当前画面里找得到 |
| 手机屏幕真正剩下多少空间？ | 先叠平台 UI，再定文字、脸部和证据的可用区域 | 缩到手机大小后，必要文字不被裁切，也不被按钮或发布信息挡住 |
| 此刻最该看哪个对象？ | 主证据优先放大，人物、字幕和解释层围绕它安排 | 关键操作不为头像留空而缩小；头像也不盖必须阅读的内容 |
| 运动是否承担了信息？ | 展示真实状态变化、卷页、推进、文字重排 | 能指出动作发生在哪里；静帧推近代替不了被讲解的真实动效 |
| 返工后什么必须保持？ | 锁定口播源段、字幕样式、时间基准和已确认项 | 局部换画面不会顺带删句、换字体、移动后段或改总长 |
| “完成”由谁看到的结果定义？ | 工程、渲染、文件保存和平台预览分开记录 | 工具成功、几张抽帧、导出完成、文件落盘、已发布各是各的状态 |
| 第一秒为什么值得继续看？ | 相关问题、痛点、反差或结果优先于寒暄 | 前三秒能说出观看收益，不靠随意炫技或硬裁半句 |
| 怎样建立全片预期？ | 开头给结构总览，换章插过渡卡，导航标出当前段 | 观众能说出这条分几部分、现在讲到哪 |

## 2. 先做什么，什么时候检查

### 开剪前：少量代表画面先过关

- 从当前工程、实际录音和现行简报接续，锁定用户已明确的内容、口播速度、字幕皮肤、人像策略和交付终点；没指定的不套上一条的参数。
- 制作前按用途分别确认口播字幕、主标题/关键词和导航的字体、字色、底条与阅读层级；只改一层时不连带覆盖其他层。已确认的样式直接复用；新出现、还没定的镜头类型先查代表画面，普通局部修正不重复选型。
- 建一张轻量素材对应表：`口播/词级时窗 → 观众要看什么 → 来源及高光源入点/出点 → 实际可见动作/证据 → 进入与退出 → 人像/字幕/平台遮挡`。按整条语义覆盖检查，“素材数量够”不等于“证据够”。
- 优先找现成的真实录屏、对话、候选和结果；不够时用核实过的原话加对应结果或简洁归纳补位。结果展示和操作证明分工明确，归纳文字不伪装成原生聊天或历史录屏。
- 新片先做覆盖全部画面类型的 30 秒样片（见[样式卡](xhs-style-card.md#5-制作与验收)），其中包含最长字幕、真人与证据同屏和顶部导航。已有确认版式就沿用；只有方向未定或用户要求先看候选时才等选择，普通修正不重开审批。

### 粗剪后：先看整条，再做局部精修

- 个人感受、过渡和收尾可以回到真人，不要求每句都配一张图；证据、B-roll 和人像的时序服从本条要求。
- 检查是否连续反复出现同一对象、同一截图或同一个运动机制，按[每 3–5 秒有效变化](editing-rules.md#观看节奏与口播切口)安排新信息，不机械闪切。前后段比对源区间和实际画面，不用同一张普通卡片或页头反复填空；能用现有的不同高光源段解决，就不批量生成新素材。
- 同一讲解对象再次出现时，要带来新的输入、修改或结果；换候选时先看源片段的动作，再看最终同屏的遮挡。
- 对比相邻镜头的可见上沿、主体中心和文字基线。同类播放器/结果窗口统一；纵横比例不同可以换构图，不强行统一尺寸。先修位置和源段，再决定要不要短叠化，不用转场遮掩错位。
- 主画面优先，人像按叙事分配出现时段。用户改变显隐要求时更新所有适用区间，“演示时可以隐藏”不扩大成后半程一直隐藏。头像位置同时受字幕带和主证据约束，不挪到字幕下方的角落。
- 人像形式按[样式卡](xhs-style-card.md#1-开剪前要问清的两件事)。先把主素材放大到手机上看得懂，再给人像找非关键位置；高而大的录屏或目录需要占主体空间时，小框或小头像可以暂时让位。人像不盖标题、数字、按钮、关键操作和脸。
- 清单、排名和网站合集类内容另读[网站与清单案例](cases/xhs-website-list-cases.md)。
- 大人像和案例画面的顶部承载分开检查：导航避开脸部和正文。默认导航 A 的标签、分段条和半透明蒙层都要在安全区内看得清；用户另选 ChatCut 皮肤时按 `bela-jindutiao`。
- 需要冲击力时，主要缩短进场、让重点及时落位；停留阶段给足观看和阅读时间，退出接到下一个对象。并排看完成态，再连续看衔接，避免每页同一种滑入、过量回弹或持续晃动。换配色代替不了对象和动作机制的变化。
- 人物和文字的先后顺序跟讲述任务走：提问、回应、步骤、结果各有进入节点；相邻解释段检查动作机制是否重复。冲击动效优先给核心强调，停下后文字和人物稳定可读，不为了差异让每个字都翻转或让人物一直抖。

### 交付前：检查真正会发布的画面

- 对照实际小红书预览/UI 蒙版，检查顶部按钮、左右边界、底部账号/文案/进度和互动区；原视频或截图内部的小字、英文、导航、数字和字幕也要查，不只查新增文字。
- 改过安全区、裁切、源段、速度或转场，就重看受影响的入场、动作中、出场和最拥挤状态，并连续播放检查动作和衔接。截图只证明被查的那一帧。
- 整片导出要明确授权。导出后核对最终文件的实际规格、首尾、改过的位置和声音切口；平台预览裁字时回到布局修正再导出，旧文件不会随工程自动更新。
- 还没拿到文件或平台预览时，写明待验收范围，不提前宣称发布通过。用户赶时间时先修会裁字、看不清、漏句、黑场或错位的问题，停掉额外装饰。

## 3. 安全区是构图输入

- 用真实发布模板或用户给的手机截图。先核对实际视频区域及其缩放/裁切方式，再把遮挡区域映射回母版；手机外框、截图边缘、编辑器缩放框都不是视频边缘。
- **正式界面上沿（Lidali 于 2026-11-06 确认）**：在小红书竖屏教程中，以[用户标红的画面](../assets/xhs-safe-area/正式界面上沿-用户红线.png)定位真实网页／工具界面的上沿。该参考是局部截图；按成片宽度与同一界面边缘换算，在本条 1080×1920 母版约为 y=150（高的 7.8%）。相同构图沿用此线，有更新的实机模板则重新映射。单独核对界面内关键字、数字、脸和操作目标的遮挡。人像与标签优先分配到界面下方可用区。首进、切换类型、滚到第三条回复和片尾再进主页均要从导出文件抽帧复核。
- 没有更准的模板时，1080×1920 先从顶部约 260px、左右各约 96px、底部约 300px 的重要信息留白开始试排，其他画幅按比例换算。这是关键文字/脸部/操作目标的本地保守起点，**不是整张录屏必须缩进的外框，也不是平台官方标准**；真实 UI 遮挡优先。横向窗口保持原比例尽量用足可用宽度，按实际证据位置避让；完整结构与局部取景见[录屏精修](xhs-motion-audio.md#2-录屏完整展示结构压缩等待时间)。
- 背景、非关键信息和底条可以延伸到边缘。检查的是变换后的实际字形、斜体外伸、数字、脸部和关键证据边界，不只是文本框坐标。右侧互动按钮可能需要额外留白。
- 文字放不下时依次处理：删无用的制作标签和重复解释 → 分句/分屏 → 调图文分区和素材焦点 → 合理调字号。不横向压扁，不用极小字号塞满窄栏，也不为保住双栏裁掉首尾字。主画面文字可以换行/分屏，口播字幕保持单行、按语义分时显示，两者不混用。
- 小红书字幕按[现行字幕规范](xhs-subtitles.md)。样式锁定和位置适配分开：保留用户的字号、字体、底条和时间；需要避让时改布局并预览，不用其他平台的皮肤覆盖。
- 导航默认 A（见[样式卡](xhs-style-card.md#2-画面)）：先判断这条要不要导航，要的话检查标签、分段条和蒙层的对比，以及换章过渡卡不挡主证据。用户点名 ChatCut 的 bela-jindutiao 皮肤时按那个 Skill。关键信息都放进真实可用区，不照搬旧的起排坐标。

### 人像形式

按[样式卡](xhs-style-card.md#1-开剪前要问清的两件事)由视频类型决定：教程类用小框陪伴，唠嗑类用大头像，竖椭圆小头像是可选形式。不论哪种，都要看得到完整头部、头顶留白、脖子和双肩，嘴型与原声同步，不挡字幕、关键证据和导航。制作和验收方法见[人像精修](xhs-motion-audio.md#1-竖椭圆头像先看人再定蒙版)。

### 通用证据检查

- 说到操作就展示操作，或可复核的请求与回复；只播漂亮成品证明不了怎么做。用户提供的新录屏先按内容盘点，接到对应口播，不因旧素材顺手就继续循环旧图。
- 工程回看、核实原话、真实候选、真实操作和最终成果在内部素材表里保留来源；文件名、版本、工程标签、用时等没有观看价值的小字不烧进视频。必要的真实性说明保持简短；拿掉它会造成误认时就换素材，不靠伪装。
- 手机外壳、视频实际内容和源画布分开量。优先沿真实机身/主内容裁切，保持比例，避免粉白矩形底板把素材变成广告贴片；有意保留背景时，确认它承担信息或空间关系。
- 多视频同屏时，先让每个关键运动各自看得见；不排成规则的小网格缩略图，前景也不挡住背景里唯一的动效或文字。头像可以盖非重点，关键证据必须露出。
- “日历在翻”“镜头推进”“图标阵列变化”用对应动作的源区间，去掉前面的等待、尾部定格和无意的循环。留够动作和阅读时间；静态截图缩放冒充不了源动画。
- 静态证据可以稳定停留供阅读，优先局部聚焦或有意义的揭示，不用持续移动的装饰代替清楚展示。
- 检查录屏自身的滚动、缩放、加载、播放器控件和历史日期。先选足够长的稳定段，不把极短片段无限慢放假装连续操作。变速后检查有效帧率和动作连续性；慢放不说成实时生成。
- 介绍页负责“这是哪个项目”，案例负责“它能做什么”。口播提到科普、故事、数据、产品发布时，换成对应类型的真实画面；提到很多风格/配方时，立刻接真实目录翻阅。同一素材再次使用时要展示新信息，不靠拉长同一画面填空。
- 按证据决定完整展示还是有意裁切。艺术作品、标志和关键结果不能无意中只剩半幅；局部放大也要让主信息完整。截图太小时先减少同屏的次要元素、调构图，不牺牲主体去给头像或装饰留固定位置。

## 5. 保护口播和 ChatCut 工程

- “去停顿/口误/重复”不包括删完整观点、适用条件、必要的使用引导和真实的个人收尾。对比保留稿和原音频，拿不准的完整句先留；用户要求保留的句子交付时逐句核对。原声指向下方小工具等发布入口时，粗剪保留承接本片目标的引导，审片说明标“入口待核对”；缺挂载证据不等于应删句或已挂载。发布前核对实际入口；不可用时先给替代说法，按本次授权处理原声，不擅改锁定句。
- 删除收尾或改末段时，检查人声结束点之后有没有残留的底片、旧资料卡、字幕、进度条或配乐，按已确认的收尾统一实际结束范围。接续记录只维护一个现行状态入口，旧秒点、旧版式和被否决的方案明确标为历史。
- 修黑屏先区分：没有素材覆盖、图层错轨/错时、蒙版或透明度、源片空帧、没加载。一张黑图不能断定素材没导入。没经本次授权不移动后段来掩盖局部问题。
- 用 ChatCut 时，Script 工作流、轨道与时间单位、MG 资产、导入/重连和重剪同步的规则见[调用地图的 ChatCut 工程保护](skill-routing.md#chatcut-工程保护)；不用 ChatCut 时不读。

## 6. 用反例做对抗检查

先主动找会失败的情形，再选最小修法。局部返工修改受影响项，同时按[整条复核](editing-rules.md#整条复核与同类问题排查)只读排查全片同类问题；首次整片和发布交付覆盖全部项，不重做已确认的稳定段。

| 反例/对抗问题 | 应做的决定 |
|---|---|
| 只有三条成品，观众能复述修改操作吗？ | 补实际输入、对话或候选证据；成品数量不等于过程覆盖 |
| 关掉音频，画面里能找到“这里”“后面也改”指向的对象吗？ | 对象和修改范围同屏或连续承接，不放无关配图 |
| 每页都换图，但看起来仍是同一架纸飞机？ | 审核对象和动作机制的重复，换语义证据而不是换颜色 |
| 动态视频播放中只有纸张静立，开场还等了几秒？ | 核对源段的真实动作，不用定格或慢进场填时长 |
| 大图、头像、字幕、平台 UI 同时出现，还读得到吗？ | 按实际字形和证据边界重排，删次要层 |
| 加叠化能掩盖录屏窗口突然上下跳吗？ | 先统一可见窗口、避开录屏内滚动，再决定过渡 |
| “压短一点”是否误删了一句条件或“今天就到这里，拜”？ | 对照原句差异；保留指定内容，时长目标不替用户删观点 |
| 渲染完成就能说用户已拿到文件、已经发布吗？ | 渲染、下载落盘和平台状态分开查；缺哪层证据就标哪层待确认 |
| 去口水后把判断或操作顺序删没了？ | 回听完整前后句，只去无语义的垫词，保留让句子成立的连接 |
| 录屏看似放大了，却只露半行字或丢掉窗口关系？ | 先确定整体/操作/局部任务，保持比例用足宽度；完整行、按钮与结果逐状态查 |
| 身后花字还在，前景人物先结束或像定格？ | 同查底片/前景的源时钟、内部延迟、可见起止与解码；连续播眨眼、嘴和手 |
| 文字溢出检查没报错，图形之间却互相压住？ | 每个手绘页在元素最全的那一刻抽帧，全片每 1.5 秒拼总览检查 |
| 删掉一段口播后，过渡卡或动画停在画面上不走？ | 检查剪点前后 2 秒，落进删除区间的时间点重新安排 |
| 声音库名字合适，手机上却听不到或只剩闷响？ | 试听实际起音/尾音，比较音效开关与场景匹配；检查多层衰减，不继续统一压小 |

## 7. 交付只报真实状态

简短记录：`已修改范围 → 可定位的工程/文件 → 看过哪些合成/播放/声音/平台状态 → 还没验证什么`。完整渲染、文件落盘、最终 MP4 检查和平台上传预览各有证据后，才升级对应状态。不顺带未授权的发布，也不反复催用户确认已授权的修正。

复盘时把初次简报没说清的节奏/身份句、后来新增的重剪方向、助手知道规则却没执行、工具渲染和状态不一致分开，不混成同一种错误。缩短时长或增加动效证明不了完播率提高，效果要等发布后的数据。

## 8. 复盘到 Skill 的闭环

适用于两个平台的剪辑方法进化；单片美术选择不升级为跨片皮肤。

1. **先确定复盘终点。** 审片交付具体问题；经验复盘交付原因和可复用的判断；明确要完善 Skill 时，交付规则差异、写入位置和回读验证。只维护规则时不调用编辑器改工程，也不渲染或导出。
2. **每项反馈形成可执行链。** 记录“可观察问题 → 失效原因 → 命中的既有规则 → 增补/替代内容 → 下次何时检查、如何通过”。已有规则没执行时，补执行触发点和验收证据，不再复制一条近义禁令。
3. **按性质路由。** 剪口、选材、布局、角色动作和验收方法进命中的 Skill 专项；明确的跨片偏好按授权写入平台规范；秒点、大小、源资产、榜单数字和单片进度只留案例记录（`references/cases/`）。修改历史写进变更记录，规则正文只保留现行内容；画幅或样式要求变化时在变更记录里标明替代关系，确保旧要求不再生效。
4. **最小合并并验证。** 优先修订既有条款，确有新判断才加规则。检查入口能到达、没有重复和冲突、条件和通过标准可执行；用本次失败案例和一个已有的正常场景检验有没有误伤。“规则已写入”和“已在下一条视频验证有效”分开说。
5. **交付规则变化。** 简短说明本轮增强了哪些判断、写在哪、验证了多大范围；没获授权的候选单列。不给没检查过的工程补写验收结论，不因复盘扩大视频修改范围。

反例与规则检查记录：[Little Move 多轮返工复盘](cases/littlemove-review.md)。只有复盘或检查规则是否覆盖相同失败时读取，不沿用其中单片音量和时间点。
