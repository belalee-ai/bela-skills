# 视频号：选镜、标题分层、字幕修复与局部返工

**只用于 Lidali 本人视频号**，是[视频号分支](channels.md)的按需专项。科技解说、大会集锦、多观点原声视频遇到选镜、标题、选曲或局部返工问题时，读对应小节。小红书、红发魔女、课程和其他项目不适用；已确认的标题和字幕规范不因本文件改变。

## 1. 先解决观众的问题，再加效果

| 反馈 | 先检查什么 | 优先处理 |
|---|---|---|
| 太长、看不懂 | 是信息过量、术语难懂，还是段落边界不清 | 重复内容才压缩；关系不清用流程或短释义；多观点用段落提示和序号 |
| 都是同一类画面 | 实际画面覆盖、重复对象占比、最长不换镜时段 | 重新选镜、分配时长；花字掩盖不了素材不足 |
| 字太多、太乱 | 标题、注释、字幕是否在重复同一件事 | 先删重复、合层、缩短，再统一字体字重和入场；只换字体不算解决 |
| 需要讲解序号 | 有几个实际语义段，现有注释能否承载 | 在同一行前加段落编号，不另叠一行章节标题 |
| 某时刻缺字幕 | 字幕源、卡片范围、样式覆盖与实播结果 | 局部定位连续显示问题；卡片里有文字不代表播放时显示 |

“太长”既不等于默认删原声，也不等于保留时长只加字，要结合后续指令判断，并说明本轮是否改变时长。改变原话或选段走 Script 语义编辑；只换画面时保留锁定音频。

多观点集锦可以有多个分段，但都服务同一个观看承诺。

## 2. 先盘素材，再排换镜

长原片先抽看全程分布，再细看各语义段附近的候选窗。记录实际看过的范围：抽帧概览、候选短段复查、全程连续观看是三种不同证据，前两种不能叫“已看完整片”。

排初剪前先盘点各语义段的素材覆盖和缺口，备好能承担不同观看任务的镜头，而不是先用少量图片循环铺满、等用户指出重复。每个候选镜头记录：`成片时段／对应原声与概念／源片范围／可见对象与动作／真实或示意／构图与声音／重复使用情况`。检查同图、同一源段和相似构图的重复；有意回看或对比要有叙事作用。同一原片的不同片段可以当不同镜头；把同一镜头机械切成几段不算换画面。

- 每段先有对应证据：讲企业知识看相关结构，讲设备交付看设备与流程，讲训练看训练演示。有趣的机器人画面不能包揽其他主题。
- 开头的动作也要和首段讲述相关，不为吸睛抢先放后段对象。扫一遍镜头表，看有没有某个对象跨主题反复出现。
- 在语义匹配的候选里交替选现场、主体细节、结构、操作和结果。讲人员经验、操作和制造时优先真实人员、工序和产线，抽象传承图或仪式化示意不当默认替代；只有解释不可见机制时才用示意。通用行业素材不能充当特定国家、工厂或新闻现场的证据。没有合适素材就指出缺口或沿用相关现场，不拿无关库存画面凑数。
- 同场的一台设备不能剪成“这段训练实际用了它”的证据，必要时标“同场设备画面／示意”。真实、仿真、还原标识只在对应素材时段出现。
- 用户指定“每 N 秒换镜”时，把它落到当前镜头表和真实画面；最后不足 N 秒的尾段保留完整。交付时回读相邻镜头，确认对象、景别或动作真的变了，而不只是建了等长片段。N 不成为后续默认。
- **画面切换和原声裁切分开。** 连续原声里可以句中换 B-roll；剪动原声时才按字词、气口和回听定切点。辅助视频的音轨默认静音或压到无声，不叠出第二份讲话。

候选镜头检查开头、中段、末尾，有内部切换、黑场或字幕残留就换范围。涉及细节阅读、裁切或运动时再看相邻帧或短段，一张漂亮帧代替不了运动检查。图表缩到手机上看不清，就调整焦点或换素材，“素材已加载”不等于可读。

## 3. 顶部标题、图内注释、底部字幕各司其职

写标题前先从口播和真实来源提炼一句观看承诺：谁发生了什么变化，新增的能力、合作或机会具体是什么。用户说“以前没有、现在有了”时，先定位“有了什么”；材料能确定就直接写，指代仍不唯一且影响结论时只问这一点。两行标题分别交代主体／事件和变化／价值，避免重复地名、行业，或只写“补齐拼图”这类抽象结论；局部的新合作不能写成整个国家此前没有某项技术。

| 层 | 负责什么 | 控制方式 |
|---|---|---|
| 顶部固定标题 | 人物、事件、整片主题 | 保留已确认样式，不承接逐段摘要；写完整大会名时先核对官方名称、地点和缩写，不补“国际”等来源里没有的词 |
| 图内注释／梗概 | 当前段的核心关系或一句短释义 | 先找画面内空位，避开脸、操作和证据；标题下的空隙不是固定注释槽。用户指定了位置就沿用 |
| 下方口播字幕 | 完整原话／译文 | 沿用平台字幕规范和用户手调值，不用第二张大卡重复 |

出现密度问题时，注释先收成一行“序号＋关键词／关系”，序号跟语义段变化，不每镜重编。短释义用来解释术语，不是复制另一句逐字稿；每屏少一个重复层比多一种花字有效。

字体按角色收敛，优先复用当前工程可读的字体家族；注释一般弱于主标题，不额外引入一套强风格英文字体。用户说字形要“正常”，就检查实际拉丁字形、合成斜体和字距，按本次要求替换，不机械坚持旧默认。字重、字号、颜色、底条占地和动效一起检查，只回读字体名不够。

在手机尺寸下比较几个不同段落的完成态和入场峰值：标题仍最突出，注释可读但不抢字幕，编号不产生新的章节行。信息已多时用克制的揭示，不默认散字飞入、震动、发光或扫光。字号、坐标、颜色和本次字体只记在当前工程，除非用户指定为后续默认。

## 4. 字幕缺行与样式修复要查连续区间

1. 读当前时间线的字幕来源、原文／译文、卡片范围、词时间、继承样式和单卡覆盖，先定位问题类别。外语句子和术语的显示行数要看实际渲染，不按字符数推断。
2. 先做最小修复：正确文本、语义分组、单行容量和中英文位置。保留测得的原文时间；译文按对应原声的语义区间对齐，人工估计的时间如实标注，不冒称 ASR 词级测量。
3. 修完回查问题前后完整一句、卡片进出边界、中间停留和相关术语，不只截缺行那一帧。改风格或合并重分组后，还要看其他卡有没有被牵连。
4. 发现一处字幕问题，就按[共用整条复核](editing-rules.md#整条复核与同类问题排查)枚举全片同类卡片，查遗漏、重复、断续、溢出和双语重叠，也看图内文字；工具给出的文本列表证明不了实际持续显示。按工具提示在一个修改阶段结束后刷新并检查差异，不在每次小改后反复重建。
5. 遗留程序或样式冲突一直在，先读回和诊断；重置／重建整条时间线不是局部字幕反馈的默认步骤。确实要重建时保留原工程恢复点，核对原声、片段映射、字幕、音乐、淡化和总长，最后把用户可见的编辑器切到明确的当前版本。

## 5. 选曲比较前置，卡点单独验收

试听比较沿用[新闻专项的配乐与交付](news-explainer-review.md#配乐与交付)，音量与听感检查沿用[视频号分支 §3](channels.md#3-声音)，本节不另设响度、倍速或曲风预设。

- 新片曲风或强度未定时，默认先给 3 段差异明显的短试听，再把选中的接入整条。用户指定了数量、已有确认曲目或要求沿用既有方案时按原要求，不加选曲关卡。优先用许可明确的已有素材，不为比较批量付费生成。
- 把“科技感、动感、震撼”拆成鼓点推进、旋律密度、音色强度和开场职责，结合参考样片和已有反馈选候选。“动感”不自动等于重电音，“震撼”不自动等于宏大管弦乐；已明确的方向不反复问，本次选曲也不变成后续固定曲风。
- 用户选中的是那段试听及其和口播的关系。接回时沿用该源段起点和接近的音乐响度，再查整条后半段、乐句衔接和淡出；不同时换段落、曲风和音量，免得试听和工程是两种效果。曲目确认只代表选曲完成，整条混音另行验收。
- 有节拍的音乐不等于画面已卡点。需要卡点时，对齐口播语义、真实画面动作／切换、音乐重音和必要音效，实际播放检查；不为踩每一拍切坏口播。动作片的峰值定位按[动作配乐专项](channels-action-audio.md#先口播再找音乐与动作落点)，其他题材不照搬它的 ABC 曲库或弦乐偏好。

## 6. ChatCut 局部修改的实现边界

只在命中对应问题时用；当前工具 schema 优先于旧调用经验。

- 先确认当前工程、时间线、画布和用户手调值，再选本次授权的 Hosted／Desktop／其他编辑器。某个接口不可用，不代表素材无法下载或没有其他本地方法；用户已否定的产品不擅自切换过去。
- 资产创建、时间线放置、用户正在看的时间线是三件事。复制片段时显式给起帧、时长、源偏移、轨道和声音状态，不假定复制会保留原起点；结构变更后回读实际落点。
- 配乐压低按当前工具的实际触发方式说明。跟随轨若按口播片段重叠范围压低，连续口播会让整段配乐一直被压低，它不会识别句内停顿自动恢复。回读片段增益与轨道压低的叠加结果，不为制造音量起伏切断本人原声。
- 改已有 MG 前读代码、属性 schema 和 revision；实例调整优先用实例覆盖。新增字段用完整属性定义，`editableProperties`、属性默认值、源尺寸和实例布局各是各的更新字段。
- MG 自然框尺寸与片段比例锁定时，不同时改宽高去拉伸字体，也不把裁切当放大。确实要改源自然框，就新建尺寸正确的资产，只替换目标实例，保持源时长与放置时长一致，改完看完整合成。
- 引用文字动效库时复用当前共用源码；适配组件保留实际字形内容和全部依赖，显式读取编辑属性。先处理验证明确报出的错误，不用换视觉方案掩盖字段或代码错误；不阻塞的分析警告不反复重写。
- 预览里标题／字幕消失时，先对照编辑器实际状态、轨道和字幕可见性、播放状态和当前 revision。必要时暂停预览抓相邻新帧，判断是旧快照还是捕获问题；换一张截图不等于修好了工程，没定位前也不删标题、不重建字幕。和用户同时操作时不反复抢焦点。
