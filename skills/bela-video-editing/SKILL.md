# Lidali AI 账号剪辑流程

本文件是唯一完整的流程入口，只负责判断阶段、交付范围和该读哪个文件；具体规则都在 `references/` 里。全局同名 Skill 只转入这里。只适用于 Lidali 本人的小红书和视频号，不混入其他作者。

## 先判断本次任务

- **内容底线，自 2026-11-06 起对两个平台、所有剪辑阶段生效。** 禁用国家层面议题、政治内容及任何制造或煽动对立的表达。选材、入轨和导出验收均须执行[内容底线与淘汰规则](references/editing-rules.md#内容底线与淘汰规则)；命中即撤换，公开原帖、指定参考、热点和真实录屏同样适用。
- 从当次要求和现有材料确认平台、对象、已有稿件/录音/工程、交付终点和锁定项。已知信息直接沿用；只有必要信息不唯一、而且会改变结果时才问关键问题，不做固定问卷。
- 从下表最接近当前目标的一行接续，局部修改直接进局部行；已有的确认稿、录音和工程不重做。只要稿件就不建工程，只要定版就不渲染整片，只维护 Skill 就不改视频。
- 小红书教程使用真实网页或工具录屏时，先按[用户标定的正式界面上沿](references/xhs-editing-review.md#3-安全区是构图输入)布局，再安排头像、数字和贴图。
- 做分镜、动效或剪辑前读项目 AGENTS.md〔资料：项目规则〕，执行唯一音频、分时进场、画幅、四项规格、安全区和最终画面验收规则。涉及账号方向判断时才读工作库 README〔资料：工作库 README〕和AI 账号 README〔资料：AI 账号 README〕；已有明确工程的局部修改不重复加载全部背景。

### 开剪前补齐五项

新片或新一轮完整剪辑先从聊天、文件和现有工程查以下五项；缺项集中简短询问，已经回答的直接沿用。局部修正、审片和 Skill 维护不重开问卷。

| 必须明确的事 | 未知时怎样问/判断 |
|---|---|
| 口播是否已有 | “口播视频/录音已经录好，还是目前只有稿件？”已有路径或上传素材就先打开检查内容、声音和代表片段，不再问有没有；没有成音先做可录稿/语义分镜 |
| 主剪辑工具 | 用户已指定或已有工程时直接沿用，不重复问。未知时先推荐并确认“这条用 ChatCut 还是 Remotion？”，确认后才建立粗剪母版或制作整条剪辑预览；不能先用 FFmpeg 出整条，再让用户追问工具。本地检测、转写和辅助片段可先做，但不替代所选主工程；工具受阻时先说明具体阻塞与可用替代，不默默切换 |
| 素材怎么准备 | “素材你来上传、我来录屏/制作，还是先用现有素材、缺的再补？”先盘点真实素材；缺口逐项说明缺哪句话的什么证据、助手能做什么、哪些确需用户补录，不笼统把全部素材交回用户 |
| 是否需要进度条 | 制作前主动给出“建议加/不加＋原因”，未知时一并确认。步骤/多章节可推荐导航，短片/高密度展示可不加；已有选择不重复问，不把无进度条当漏项。小红书默认导航 A（见[样式卡](references/xhs-style-card.md#2-画面)），ChatCut 工程或用户点名皮肤时才调用 bela-jindutiao；记录不加/所选模式与本条语义节点 |
| 目标时长和人像形式 | 没有默认秒数，用户没给时问“这条大概剪到多少秒？”。人像形式按视频类型（教程用小框陪伴、唠嗑用大头像），看不出类型时一并问；小红书细则见[样式卡](references/xhs-style-card.md#1-开剪前要问清的两件事) |

五项、交付终点和锁定项写进现有 brief/镜头表即可；接续时读取，不再建第二套配置。交第一版时标明当前主工程/工具与本次是否已写回；本地预览不能当成已写入 ChatCut。确认前可继续素材盘点与内容理解，不先铺整条。

## 平台分支：命中时读取

| 平台 | 主文件（粗剪、画面、验收） | 字幕 | 按需专项 |
|---|---|---|---|
| 小红书 | 先读[现行样式卡](references/xhs-style-card.md)，再按[小红书分支](references/xhs-editing-review.md) | [个人字幕规范](references/xhs-subtitles.md) + [确认样张](assets/xhs-subtitles/reference.png)：制作/更换样式时读规范并看样张，只校字时沿用当前样式 | 制作/修复头像、完整录屏、身后花字、抠图、闪现转场或音效时，读[动效与声音精修](references/xhs-motion-audio.md)的命中节 |
| 视频号 | [视频号分支](references/channels.md)：粗剪、视觉与字幕、声音、验收 | 在视频号分支 §2 | [选镜、标题分层、字幕修复、ChatCut 局部返工](references/channels-montage-review.md)；[动作配乐与卡点](references/channels-action-audio.md) |
| 两平台共用 | [共用剪辑规则](references/editing-rules.md)：画幅、素材整理、每 3–5 秒有效变化、剪口回听、整条复核、混音通则、导出、封面 | — | [新闻与真人热点](references/news-explainer-review.md)；[工具调用地图](references/skill-routing.md)；[OneTake Pro](references/onetake-workflow.md) |

- 每个参数只在一处定义：画幅和 3–5 秒节奏在共用规则，小红书 1.1× 在小红书分支，视频号 1.2× 和 0.6 秒停顿在视频号分支。两个平台的参数不互相搬用。
- 人像/录屏/抠图先自检最难的代表片段再扩展；声音先验证真实切口与可听效果。用户已定风格不重复选型，普通修正不重开审批；外部工具不可用时按精修专项尝试可用的本地/原生实现，不能把参数写入当成观感、听感通过。
- 进度与章节导航先判断要不要。小红书默认 A（一排短标签＋分段进度＋开头结构页＋换章过渡卡，见[样式卡](references/xhs-style-card.md#2-画面)）；ChatCut 工程或用户点名皮肤时用 bela-jindutiao，其默认 C、原粉色 IP 只在明确选原版时用。按本条音频校时，静态选型后先做短动态测试。
- 单片的坐标、帧号、响度在 `references/cases/`，只作调试起点。没有需要就不加载历史或能力全表。

## 资料位置：缺什么就问，不猜路径

本 Skill 里带〔资料：名称〕的地方，指的是下表里的外部资料，不是写死的路径。用到某项资料时：

1. 先看当前对话、项目简报或工程里有没有它的位置，有就直接用。其次看下表的默认位置在本机是否真实存在，存在也直接用，不用多问（在作者的 Mac 上基本都存在）。
2. 没有就问用户一句：“这一步需要〈资料名〉，你有吗？放在哪里？”用户给了路径就按这个路径读；用户说没有，就按“没有时”那一列处理。
3. 不要自己去猜路径、全盘搜索，也不要因为找不到就跳过不说。问到的位置记进当前项目简报，下次不再问。

| 资料名 | 用来做什么 | 作者本机的默认位置（别人以实际为准） | 没有时 |
|---|---|---|---|
| 项目规则 | 唯一音频、分时进场、画幅、四项规格、安全区、最终画面验收 | 工作库 `01-AI知识普及账号/05视频分镜/AGENTS.md` | 按本 Skill 和共用规则做，并告诉用户缺这份 |
| 工作库 README、AI 账号 README | 判断账号方向 | 工作库根目录和 `01-AI知识普及账号/` 下的 README.md | 问用户账号定位；已有明确工程时不需要 |
| 视频号口播说话风格 | 视频号写稿 | `05视频分镜/视频号口播说话风格.md` | 问有没有样稿；没有就保留用户原话 |
| 标题模板 | 视频号双行标题 | `00-原始素材/1017-视频号标题模板/README.md` | 先出两种标题排版样张让用户选 |
| 视频号配乐库 | 选曲、配乐目录 | `00-原始素材/视频号常用配乐/`、`05视频分镜/1022-宇树H2X/常用弦乐配乐池.md` | 问配乐放哪；没有就先问是否允许另找，不擅自下载 |
| OneTake Pro 源码 | 连续形变动效 | `01-AI知识普及账号/技术源码/onetake` | 不用 OneTake，改用调用地图里的其他路线 |

| 日系线条动态样片 | 日系线条动作节奏参考 | `05视频分镜/videos/belalee-japanese-line-motion/` | 问有没有；没有就跳过这个参考 |
| 单片案例资料 | Roadster、滑板少年、马斯克赠股等旧片的复盘与证据 | 各片目录 | 可以跳过，规则已写在本 Skill 里，只在溯源时才需要 |

其他 Skill（`bela-spoken-script`、`bela-broll`、`bela-text-motion-library`、`bela-jindutiao`、`remotion-best-practices`）按名称调用：已安装就用，没装就告诉用户缺哪个以及对结果的影响，不自己假装执行。

## 唯一阶段表

用户给了模仿用的视频、素材文档或脚本，先按[指定参考的复用顺序](references/editing-rules.md#指定参考的复用顺序)找出能放进本次稿件或时间线的部分，再按下表接续。

| 当前材料或请求 | 必要动作与读取入口 | 交付物与停止条件 |
|---|---|---|
| 只有选题、链接或资料 | 核实关键事实和来源，确定一个观看承诺；时效信息查一手来源，不从竞品文案反推事实 | 讲述重点与素材缺口；没要求写稿时不展开制作 |
| 写稿、改稿或确认稿待录音 | 用 bela-spoken-script 写稿；继续剪辑时由本阶段表接续。本人视频号同时读口播说话风格〔资料：视频号口播说话风格〕，保留确认内容与真实表达 | 当次要求的稿件或可录稿；缺本人录音时交必要的录音标记/语义分镜，不自行改成 AI 配音，不猜词级时间 |
| 新素材入库、录音粗剪或真人/录屏粗剪 | 先盘点来源、尺寸、声音和可用段，读[共用粗剪通则](references/editing-rules.md#粗剪通则)和平台分支的粗剪节；用当前工程，按语义、波形和回听取完整顺畅的版本。用 ChatCut 时先读所用表面的基础 Skill，导入或剪口播时才读对应任务 Skill | 可编辑粗剪和唯一口播来源；按平台核对速度，保留完整字词、自然气口和指定内容。回听通过后锁定时间基准，待听按[共用切口规则](references/editing-rules.md#观看节奏与口播切口)交接。不调用 ChatCut 内置 AI 自动剪辑 |
| 音频已定，需要字幕与校时 | 从实际口播取时间戳，校字并按语义断句；ChatCut 用 transcription，文件转写/字幕校对按需要选对应 Skill；应用平台字幕规范 | 校正后的字幕和真实触发点；没有唯一音频时只做语义分镜、时间待校，不精确制作动效 |
| 需要分镜、标题或构图定版 | 按口播对应输入、操作、修改和结果；新片检查前 3 秒，教程默认一个小点，已选定的集锦用一个观看承诺串起分段。读平台分支；做标题时才读标题模板〔资料：标题模板〕，效果未定才选型 | 画面对应表和所需完成态；复杂或未定的构图先做带平台 UI 的代表画面，用户只要定版时到此停 |
| 已定版，要做动效、B-roll 或接回母版 | 按[调用地图](references/skill-routing.md)选一条主路线，按真实词级节点进场；只需要提示词时停在策划。制作片段接回原母版，字幕、进度条和声音统一校时 | 可编辑组件或匹配母版的片段、接回位置；已授权制作并接回所必需的片段渲染属于制作，不等于整片导出 |
| 已有工程，只改字幕、进度条、画面或声音 | 先读目标工程当前状态、用户手调和受影响区间；按平台专项查对应问题，保留已确认的轨道、原声映射、字幕时间和其他稳定部分。单纯校字沿用当前样式，不重新加载样张或套用基准值；交付前按[整条复核](references/editing-rules.md#整条复核与同类问题排查)排查全片同类问题 | 授权范围内的修改、局部验证和整条复核；只换画面不剪断原声，不重建母版或重跑前面的阶段 |
| 审看或交付工程/预览 | 按项目 AGENTS 和命中的专项，检查实际合成、连续播放、声音切口、字幕、时长和手机安全区；改混音时同时读回片段增益和轨道压低量 | 工程/预览和真实验证状态；没回听、没看最终文件或没有平台预览的分别标待验收，不用参数或抽帧代替 |
| 明确要求整片导出 | 核对源分辨率、导入分辨率、画布和导出规格，用现在的工具导出；ChatCut 读 export；检查最终文件的首尾、改动位置、后半段和声音切口，按[导出与归档](references/editing-rules.md#导出与归档)保存 | 实际能打开的成片和规格；缺文件不称已交付，没有发布证据不称已发布，已有导出授权不重复询问 |
| 要做封面 | 只在本次交付需要时进[封面交接](references/editing-rules.md#封面交接)；小红书用 bela-ai-xhs-cover-director，视频号真人封面用 bela-wechat-cover，用户指定其他路线时按指定 | 本次要求的封面提示词或图；封面不是所有剪辑任务的固定收尾 |
| 只做复盘或优化 Skill | 读当前规则和本次真实反馈，用反例定位无效、重复或冲突的条目；按[复盘闭环](references/xhs-editing-review.md#8-复盘到-skill-的闭环)写入。每日自动复盘另按[每日使用复盘](references/daily-review.md)判断实际使用、重点问题、允许修复范围与精简 | 复盘结论、规则差异、回读验证；普通 Skill 维护不改视频。每日任务只在其现行授权内修复；已确认结构/原声或证据不足的问题给具体建议，不由复盘默认重剪 |

## 选工具

- 选工具、制作和交接只查[调用地图](references/skill-routing.md)命中的项；已有 Remotion/HyperFrames 或编辑器工程继续沿用，指定的文字动效直接复用，不因新增工具迁移母版。连续形变选 OneTake Pro 时才读 [OneTake 工作流](references/onetake-workflow.md)，不混用公开版，不复制第三方源码。
- 新闻解释、真人画中画、真实素材与拼贴的取舍、配乐起势、离线重连或多轮接续，查[新闻专项](references/news-explainer-review.md)；它也适用于小红书，但字幕、标题、安全区、倍速和换镜节奏按各自平台。只读命中的问题，不重跑整条。

## 按交付范围输出

- 整片规划：观看承诺、开场、剪留依据、所需画面与声音；精确时间取实际音频，交接字段用调用地图的画面交接表。导出或封面只在本次需要时说明。
- 局部修改：实际改动范围、当前工程/文件、完成的验证和未解决项，不重复整片规划。
- 审看/成片：给可定位的产物，分清工程已写入、静帧验证、连续播放、听感验收、已导出和已发布，只报告做过的检查。ChatCut 默认停在工程与预览，整片导出和发布按本次明确授权分别执行。
- 不额外发明账号定位或复杂制作系统；个人风格以当前平台规范和本次要求为准，单片参数不自动变成长期默认。
- 复盘请求先判断交付的是审片、经验总结还是 Skill 优化。复盘先从“观众为何留下、看懂什么、凭什么相信、能记住什么”定位问题，再用最可能失败的具体片段检验解法。获得沉淀授权后，可复用的方法进对应专项，确认的个人习惯进记忆，秒点、素材 ID、曲目和单片验证状态进案例记录；已配置或抽帧通过不写成听感、成片或发布验收通过。

调用示例：`按我的视频号工作流来，素材是……，先做到口播稿。` 接续：`我录好了，继续剪第一版。` 局部：`只修这段字幕，其他不动。` 用户不需要重复列出内部 Skill 或已确认样式。
