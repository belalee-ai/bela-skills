# 归档视频、发布封面与证据图

在单条视频的工作目录保留下载的原始 MP4、已取得的原始图片，以及它们的大小和 SHA-256。Hypit、ASR、截取证据帧均读取原片。压缩只产生新的交付副本，重复执行时使用工作清单里的路径和哈希核对已有文件，避免覆盖。

## 取得真正的发布封面

从本条视频的可信作品元数据或分享页，取得明确标为该作品发布封面或视频海报的图片。核对作品 ID 或分享链接、封面字段和实际显示的图像。下载后打开图片，核对格式、尺寸及清晰度。默认站点分享图、博主头像、空白占位图、播放首帧、截图或 AI 生成图均不能充当发布封面。无法确认时，记录「未取得可核验的发布封面」及原因，继续处理视频与拆解。

仅在核验成功后，将实际编码的后缀传给 `archive_names.py --cover-ext jpg`（或相应扩展名），使用返回的 `cover_filename`。保留作品与封面的对应依据，分享 URL 含临时签名时只记录作品链接、字段及本地哈希。

## 准备交付副本

在 Skill 目录运行下面的命令。输入和输出必须为不同路径，输出的父目录需已存在。先在独立工作目录准备候选并目检，再把选中的文件写入归档目录空闲位置。视频输出采用 `video_filename`，发布封面采用 `cover_filename`，证据图保留各自的时间码标识与原始图片编码。

```sh
python3 scripts/prepare_media.py video "$SOURCE_MP4" "$ARCHIVE_MP4"
python3 scripts/prepare_media.py image "$SOURCE_IMAGE" "$ARCHIVE_IMAGE"
```

每次处理一个文件。成功返回的 JSON 含 `output`、`source_bytes` 和 `output_bytes`。状态为 `compressed` 时保存已验收的小文件；`original` 时已将原字节写入输出并说明原因。目标已存在（含符号链接）、媒体类型与扩展名不符或无法读取输入时，检查非零退出码和错误。所有处理在本机进行，工具缺失时按返回结果记录，不发送素材到在线压缩服务。

| 素材 | 压缩与核验 |
| --- | --- |
| 常见 H.264 / 8-bit 4:2:0 / SDR MP4 | 本机 FFmpeg 用 libx264 CRF 15、slow 预设，音轨直接复制。FFprobe 对比分辨率、画面比例、像素和颜色信息、编码档次、声道、帧率、逐帧时间戳和每个音频包的内容哈希与时间。对**所有帧**计算整帧 SSIM 和强调字幕、线条的亮度边缘 SSIM。体积变小且两项逐帧最低值分别达到 0.985 和 0.97 才采用。HDR、旋转信息、特殊轨道等未覆盖情形保留原字节。 |
| PNG | Python 标准库重压 PNG 的 IDAT 数据。校验每个 PNG 块，确认重新解压的扫描线完全一致，保留调色板、透明、色彩及其他数据块。 |
| 静态 JPEG / WebP | JPEG 可用本机 `jpegtran` 优化熵编码，WebP 可用本机 Pillow 做无损编码。有 Pillow 时核验尺寸、模式、逐像素数据和色彩配置；缺工具、动画、未覆盖格式或体积没有下降时复制原件。 |

在本地 Markdown 引用或飞书嵌入前，以原尺寸查看包含最小字幕、密集界面文字和细线的关键帧，核对图像透明度、颜色和字形。在同一时间码对照原片和归档 MP4，尤其留意滚动字幕、快速运动和暗部。若发现可见损失，归档原片或原图，记录原因。原图本身过糊时按原画幅重新截取证据，真实发布封面则记录源图限制。

记录采用的版本、前后字节数、质量检查和最终哈希。同步飞书时使用已经验收的交付副本，避免重复有损编码。
