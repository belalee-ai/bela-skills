# GitHub 分享发布

生效：2026-09-21。把作者能用的项目整理成别人看得懂、装得上、知道怎么开始的分享包。新发布补齐以下内容；已发布项目的局部更新只维护受影响部分，沿用已有完整说明。

2026-10-21 补充：按产品入口组织说明，区分“直接体验”和“安装开发”，增加分场景真实截图与在线演示验收；不把部署或重新设计作为每次发布的默认动作。

## 发布前先确认实际交付

读取当前项目入口和现行文件，确认目标仓库、可见性、原有改动及本次授权范围。判断它是 Skill、插件还是独立应用，按真实结构打包；不要把单文件介绍当成完整安装包。只包含运行与展示所需文件，不带入私人路径、账号配置和无关素材。

## 先把入口做成产品

- 首页先回答“是什么、适合谁、能得到什么”，再提供最短可用入口。有在线演示时把“打开体验”放在安装前；只有源码时直说需要本地运行。
- 用真实任务组织功能，例如“想实现什么 → 去哪里 → 能拿到什么”，不只排列文件名、模块名和技术栈。
- 开头放能说明价值的真实预览。各主要能力用有差异的截图或短动图支撑，给简短图注；不让用户读完整篇才知道效果。
- 安装、开发、部署、完整排错按需要拆到 docs；首页保留必要条件和入口，不堆开发日志。数量、兼容性、速度、价格等声明必须有当前证据。
- 需要产品化重写、对标或选择展示素材时读取 [README 写法与参考](references/product-readme.md)。借鉴信息顺序，不照搬作者履历、下载量、推广位、素材或未经核验的兼容性声明。

## 读者需要看到的内容

按读者的理解和使用顺序组织 README，适度拆到 INSTALL 或 docs，首页保留关键入口：

1. **用途与效果**：一句话讲清谁在什么场景得到什么结果；附真实结果或截图。说人话，避免空泛宣传、术语堆砌和凭空收益。
2. **适用 Agent / 平台**：Skill 分享须在首页明确列出 Claude Code、Codex 及与项目有关的其他 Agent。逐项区分安装器支持、文件安装验证、客户端加载或触发验证、完整功能实测。查当前官方来源，不能因为格式通用就写“所有 Agent 都可直接运行”。独立应用则说明操作系统、浏览器或平台，不硬塞 Agent 表。
3. **便捷安装**：同时给可复制给 AI 助手的安装请求，以及适用的终端命令；优先单条、少步骤。写真实仓库名和 Skill 名，按目标 Agent 给命令，交代项目级/全局范围与依赖。不虚构安装器，也不覆盖现有自定义配置来做测试。
4. **第一次使用**：给一段能直接试的请求或操作步骤，说明输入、预期输出、打开方式和自定义项；示例人物、样式和材料不要冒充硬性限制。
5. **环境与边界**：分别说明必要/可选依赖、系统、运行时、读写权限、网络、模型或 API 能力、参考图与编辑支持、账号或额度要求。只写当前任务有关的条件；未知价格和时间不猜测。
6. **验证与排错**：记录实际测过什么、在哪个环境、结果是什么；未测的明确说明。常见错误给可操作的下一步。

安装请求和长代码行按可读宽度换行。链接集中到真正能用的文档，不让读者为同一问题来回翻页。

## 截图与素材

- 先复用已确认的现有结果，再补真正缺的截图；不为凑展示而生成新图。
- 区分原始效果图、参考素材、真实操作截图和还原示意；注明用途、日期或版本。不能把旧原型截图写成当前功能。
- 将可公开的截图放入仓库并在 README 或截图页展示，写有意义的图注与替代文字；打开实际渲染页面检查文字、比例和图片加载。
- 多能力产品覆盖主要使用场景，优先展示不同机制、输入与结果；截图数量由覆盖需要决定，不设固定张数。动效产品可补真实录制的动图或视频，静态截图不能证明运动流畅。
- 本次修改影响截图内容时，更新对应截图或清楚标明旧版本，避免反复更新无关截图。
- 保留真实来源和现有许可。没有依据时不代作者声明所有第三方素材均可商用。

## 验证与上传

先完成可审阅的文件和相关检查，再在已有授权范围上传；明确要求上传已构成对应发布授权，不机械重复确认。需要新的权限或显著扩大可见性时才澄清。

便捷安装应尽量从实际公开源在独立目录验证，检查文件完整性；安装器成功、客户端识别与完整功能成功分别记录。文档局部更新不重跑与改动无关的功能测试。

推送后回读仓库可见性、远端提交、README 与截图，确认实际可访问。交付仓库、安装和截图链接，报告已发布或仍受阻。不能把本地准备完成写成已发布。

## 在线演示（用户要求时）

用户明确要求部署、上线或分享可直接打开的网址时，读取 [在线部署与回读](references/web-deployment.md)。优先沿用现有托管；纯静态 GitHub 项目可选 GitHub Pages，不为部署增加不必要的后端、账号或付费服务。

先完成可审阅的代码、构建与隐私检查，再执行已获授权的部署。上传源代码、部署在线站点、README 更新、Skill 更新分别报告结果；拿到仓库 URL 或构建成功都不等于在线站点可用。遇到需要新授权、付费或不能安全消除的阻塞时说明具体原因，不把半完成当上线。

## 适用边界

这是后续 GitHub 分享任务的默认执行方法，不授权后台自动上传，不要求追溯改造所有旧仓库，不把某一项目的手绘或人物设定扩展到其他项目。普通提交和 PR 文档按实际影响补充，不为小修改重做全部发布包。
