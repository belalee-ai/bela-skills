# 在线演示部署

只在用户授权上线时使用。不将“上传 GitHub”自动扩大为公开部署。

## 选择与准备

- 先读现有部署配置和远端状态。沿用可用托管；纯静态网页且仓库在 GitHub 时，Pages 往往能少引入一项服务。
- 确认真实构建命令、输出目录、站点路径、必要环境变量。不要把开发服务器当公网生产服务。
- Git 忽略文件不等于构建忽略文件。检查最终产物，而不只是暂存区，防止 public/ 里的历史私人素材被复制上线。
- 本地地址不得当线上地址。项目部署在 /repo/ 时核对 HTML、CSS、动态字体、图片、音频、懒加载脚本与第三方播放器各自的资源基路径。
- 重用官方部署流程；读取当前官方文档确认 action 版本与权限，只给构建/部署所需权限。不要为解决失败扩大账号权限或关闭安全限制。

## GitHub Pages 典型流程

1. 检查仓库 Pages 是否存在、发布源和既有工作流；保留已有无关配置。
2. 在项目路径构建并实际预览，核对资源和产物排除项。
3. 准备可审阅的工作流，明确分支、构建、检查、输出目录与部署步骤。
4. 在用户现有授权范围启用 Pages、推送并等待实际部署结果。更新 README 和仓库首页的体验链接。
5. 回读 workflow、deployment、线上响应，并在真实浏览器操作主要路径。HTTP 200 不足以证明组件、图片或音频加载正常。
6. 如需自动更新，仅把已授权的项目提交接入构建部署；不要顺带开启内容采集、定时任务或后台批量上传。

## 验收与交付

- 核对线上 URL、实际部署 commit 与构建结果；抽查首次打开、刷新和主要分类/操作。
- 需要自动播放的动效或媒体站点，用未点击的首次访问检查，不能只看点击后的结果。无声音轨或“音效关闭”不一定等于播放器初始静音；若音频策略阻塞视觉播放，沿用播放器正式静音能力修复，再验证主动开启音效的入口仍可用。
- 查看代表性的字体、照片、音效、控件、下载/复制行为与窄屏布局；范围按本次改动决定，不能据此声称全部设备都验证。
- 保存真实线上截图并回读 GitHub README 的展示结果。站点未可用时，给出已完成部分和具体阻塞，不能写“已上线”。
- 回滚时只针对本次部署使用已知可用提交，避免 force push、清历史或覆盖远端无关变更。

官方入口：[GitHub Pages 自定义工作流](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)、[Vite 静态部署](https://vite.dev/guide/static-deploy.html#github-pages)。
